# BlazePwifi Standalone Rental Server v0.5.2-rental.2-rc.1

This release candidate implements the audited split between **Standard Enrollment QR** and **Android Device Provisioning QR**.

## Standard Enrollment

For BlazeRental already installed.

- generated by `rental_standard_qr`;
- scanned only inside BlazeRental;
- schema `blazerental.enrollment.v1`;
- server binding only;
- 10-minute one-time token;
- no Device Owner claim.

## Device Provisioning

For a new/factory-reset, owned or authorized Android phone.

- generated by `rental_provisioning_qr`;
- scanned from Android Setup Wizard;
- exact DPC APK HTTPS URL;
- exact URL-safe Base64 SHA-256 APK checksum;
- DPC component `com.blazesystems.blazerental/.BlazeDeviceAdminReceiver`;
- minimum APK version code;
- `blazerental.provisioning.v1` server/token extras;
- optional Wi-Fi parameters;
- 60-minute one-time token;
- Android 12+ provisioning-mode/compliance activities in the Launcher3 APK;
- provisioning completion waits for Device Owner plus successful Rental Server binding.

## Fail-closed behavior

The server will not generate a Device Provisioning QR unless the release pipeline has installed exact provisioning APK metadata.

The BlazeRental in-app scanner rejects Device Provisioning payloads and tells the operator to use Android Setup Wizard instead.

Device Owner-provisioned phones do not expose the manual first-run administrator setup path.

## Validation boundary

The APK published by this RC is **PROVISIONING-TEST signed**. It is built, signed, inspected, checksum-bound, and published by the same workflow, but it does not have production signing continuity.

This RC must not be promoted to production-stable Device Owner deployment until physical Setup Wizard provisioning and the locked production signing identity are validated.

All previous R281 BusyBox, CSRF, admin/reset, and network-preservation fixes remain included.
