# v0.5.2-rental-rc.1

**Base:** BlazePwifi 0.5.2 implementation  
**Purpose:** R281/BusyBox deployment correction and version-line synchronization.

## Physical R281 regression fixed

The 0.5.0-rental-rc.3 Windows deployer successfully connected over SSH and uploaded the bundle, but failed before installation because it used:

```text
tar ... --strip-components=1
```

The R281 OpenWrt image uses BusyBox tar, which does not implement that GNU option.

The corrected deployer now:

1. connects and verifies SSH;
2. reads `/tmp/sysinfo/board_name`;
3. selects the R281-specific entry point when the board is `notion,r281`;
4. extracts the archive with plain BusyBox `tar -xzf ARCHIVE -C DIR`;
5. enters the single top-level bundle directory using POSIX shell globbing;
6. runs `install-r281.sh`.

## R281 compatibility assumptions carried forward

The adapter is based on the previously successful R281 rental deployment profile and validates:

- `notion,r281`;
- OpenWrt 24.10.x;
- `/www` document root;
- `/cgi-bin` CGI prefix;
- HTTPS :443.

EasyMode networking remains outside Rental Standalone ownership.

## Regression gates

CI refuses publication if the Windows deployer contains GNU strip-components, does not contain R281 detection/entry selection, or if a BusyBox tar extraction of the generated OpenWrt bundle fails.
