# BlazePwifi Standalone Rental Server v0.5.2-rental.2-rc.9

RC9 is an immutable prerelease for physical Android Device Owner provisioning validation.

> RC9 runtime/source is bound to the RC9 tag/release. The presence of this note on `main` does not mean `main` contains the RC9 runtime implementation.

## Security delta from RC8

RC9 pins the first accepted pending Device Provisioning identity on the phone. The identity consists of the exact Rental Server origin, one-time enrollment token and server certificate SHA-256 pin.

Android Setup Wizard may redeliver the exact same provisioning extras; that replay is idempotent. A callback with a different token, server or pin is rejected rather than silently replacing pending enrollment state. Pending manual enrollment and partial/permanent device identities also fail closed.

The guard is implemented as pure Java policy logic and is covered by JUnit in the APK build.

## Existing audited safeguards retained

- Standard Enrollment QR and Device Provisioning QR are separate schemas/actions.
- Secure enrollment protocol v2 is downgrade-resistant and retry-safe.
- The long-lived device secret is independently derived and not returned in the v2 enrollment response.
- HTTPS server certificate pinning and strict origin-only URL validation are enforced for Device Provisioning.
- Exact APK/checksum/version/signer evidence is release-bound.
- Custom DPC / GMS compatibility is explicitly scoped.
- Stable promotion requires the locked production signer and physical Setup Wizard evidence.

## Signing and validation status

RC9 uses a TEST signing identity for provisioning validation. It is not the stable production signing identity.

The dedicated RC9 provisioning workflow and the broader BlazePwifi build both passed at the RC9 release commit, but physical factory-reset Setup Wizard validation is still explicitly pending and the stable-promotion gate remains fail-closed.
