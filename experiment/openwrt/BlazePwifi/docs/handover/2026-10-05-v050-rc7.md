# Handover Log — 2026-10-05 — v0.5.0 RC7

## Why RC7 exists

RC6 run `37320920634` passed validation, Android build, browser simulation, ESP8266/ESP32, Ruijie, Orange Pi and nearly all remaining platform work, but Android Device Owner still failed at initial unpaid landing:

`ANDROID_V05_FAIL: UI missing 'BLAZERENTAL' in simulation-out/android/01-locked.xml`

The captured UI again showed ordinary Launcher3 Home.

## Root cause

The RC6 cold-start retry correctly waited for custom-left availability, but Launcher3 can restore/select the ordinary Home page later in its model-binding lifecycle.

`Launcher.finishBindingItems()` performs final workspace restore/binding work after early `onResume()`/post callbacks. That can overwrite an earlier custom-left move.

## Fix

`NexusLauncherActivity` now overrides `finishBindingItems()`, calls `super.finishBindingItems()`, then re-applies the unpaid `enforceRentalLanding(0)` boundary.

This makes BlazeRental custom-left the final post-bind state for unpaid devices while preserving:
- foreground-aware HOME enforcement;
- paid/unrestricted normal Launcher3 behavior;
- bounded cold-start retry;
- secret admin-hold hardening;
- stable custom-left page across unchanged policy refreshes.
