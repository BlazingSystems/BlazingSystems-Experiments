## Result

RC3 was **not releasable**.

Validation passed the earlier foundation/security blockers, then failed at **BlazeRental server validation** because the device-facing `cgi-bin/rental` unconditionally sourced the new `rental_update.sh` module from the production path.

Evidence:
`cannot open /usr/lib/blazepwifi/rental_update.sh: No such file`

The isolated legacy rental API tests intentionally mount only the pre-v0.5.1 protocol libraries.

## Fix

Commit:
`86ae2ed44947fa085a8069e3d193cd60ff2754f5`

The Rental CGI now:
- conditionally loads the update metadata module when available;
- returns `{"available":false}` update metadata when the optional module is absent;
- preserves the existing authenticated lease/policy response and signature protocol.

This keeps old clients/tests compatible while production v0.5.1 exposes update metadata.
