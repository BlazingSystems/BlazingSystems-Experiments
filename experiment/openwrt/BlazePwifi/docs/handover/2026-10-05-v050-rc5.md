# Handover Log — 2026-10-05 — v0.5.0 RC5

## Why RC5 exists

RC4 showed that the timer-hold fallback itself was correct, but the Device Admin enforcement service was repeatedly re-launching HOME every few seconds while the unpaid BlazeRental launcher was already foreground.

That redundant HOME enforcement interrupted long touch gestures, including the secret admin timer hold.

## Root cause

`BlazeDeviceAdminService` periodically calls `ManagedPolicyController.openHome()` while unpaid.

`openHome()` did not distinguish:
- renter has escaped away from BlazeRental (where forcing HOME is required), from
- BlazeRental HOME is already foreground (where forcing HOME is redundant and disrupts current touch/UI state).

## Fix

Added a process-local foreground marker to `ManagedPolicyController`.

`NexusLauncherActivity` now:
- marks launcher foreground in `onResume()`;
- clears the marker in `onPause()`.

`ManagedPolicyController.openHome()` now does nothing when:
- an authenticated/initial-setup admin window is active, or
- BlazeRental launcher is already foreground.

This preserves fail-closed enforcement when the user actually leaves HOME, while no longer continuously resetting an already-safe launcher.

Source contract was extended to require this behavior.
