# Handover Log — 2026-10-05 — v0.5.0 RC6

## Why RC6 exists

RC5 run `37313533078` passed every non-Android-emulator required build/simulation path but failed the Android Device Owner emulator at the very first locked-state assertion:

`ANDROID_V05_FAIL: UI missing 'BLAZERENTAL' in simulation-out/android/01-locked.xml`

The captured UI showed the ordinary Launcher3 Home/At-a-Glance page instead of the far-left BlazeRental gate.

## Root cause

The foreground-aware HOME-enforcement fixes correctly stopped repeated HOME relaunch churn, but unpaid `onResume()` still performed only a one-shot `moveToCustomContentScreen(false)`.

On cold/first boot, Launcher3 may not have created/bound the custom-left page yet. `Workspace.moveToCustomContentScreen()` is a no-op until `Workspace.hasCustomContent()` is true, leaving ordinary Home visible.

## Fix

Added bounded `enforceRentalLanding(attempt)` handling in `NexusLauncherActivity`:

- re-check the authoritative paid/unrestricted access gate on every attempt;
- ensure the custom-left container is invalidated/created when possible;
- move to custom-left only after `Workspace.hasCustomContent()` is true;
- retry for a short bounded period during cold workspace binding;
- re-assert the boundary again when pending workspace binding completes;
- preserve the foreground-aware policy changes that prevent repeated HOME relaunch churn.

Also retained the newer secret-admin-hold hardening:
- MOVE-time elapsed-hold checks;
- touch-up fallback;
- stable Blaze left panel while policy state is unchanged.
