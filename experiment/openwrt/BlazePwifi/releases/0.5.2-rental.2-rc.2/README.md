# BlazePwifi Standalone Rental Server v0.5.2-rental.2-rc.2

RC2 preserves RC1 as an immutable historical release and carries the next audited provisioning hardening set.

## What changed after RC1

- one-time enrollment tokens are now claimed under a dedicated lock so concurrent valid requests cannot enroll two devices from the same token;
- enrollment-token creation is also serialized and checks for ID collisions;
- the Android provisioning TEST APK is built from the release variant so its package ID is exactly `com.blazesystems.blazerental`;
- the TEST APK is explicitly signed, signature-verified, package/version-verified, and checksum-bound before the server bundle is assembled;
- provisioning/race validation now runs in both the Rental release workflow and the repository-wide BlazePwifi validation;
- RC release tags are immutable: CI refuses to edit or clobber an existing RC release.

## Standard Enrollment QR

For BlazeRental already installed.

- generated by `rental_standard_qr`;
- scanned inside BlazeRental only;
- schema `blazerental.enrollment.v1`;
- server binding only;
- 10-minute one-time token;
- no Device Owner claim.

## Device Provisioning QR

For a new or factory-reset, owned or authorized Android phone.

- generated by `rental_provisioning_qr`;
- scanned from Android Setup Wizard;
- exact HTTPS APK URL and URL-safe Base64 SHA-256 file checksum;
- DPC component `com.blazesystems.blazerental/.BlazeDeviceAdminReceiver`;
- minimum APK version code `50203`;
- admin extras schema `blazerental.provisioning.v1`;
- optional Wi-Fi parameters;
- 60-minute one-time server enrollment token;
- Android integrated provisioning mode and policy-compliance activities;
- completion waits for Device Owner plus successful Rental Server binding.

## Release-integrity rule

RC1 is not overwritten. RC2 uses its own tag, APK asset, checksum and server-bundle metadata. A downloaded RC2 server bundle therefore remains bound to the exact RC2 APK asset instead of depending on a mutable tag asset.

## Validation boundary

The APK in this release is **PROVISIONING-TEST signed**. It is suitable for physical Setup Wizard validation, not final production deployment.

Production promotion still requires:

- successful physical Setup Wizard provisioning on supported Android/OEM targets;
- recovery/use of the locked BlazeRental production signing identity;
- rebuilding the provisioning APK and checksum with that production identity;
- a final no-regression audit.

Existing R281 BusyBox, CSRF, admin/reset, network-preservation, ESP and full-conversion safeguards remain included.
