# R281 live audit — 8 October 2026

Status: audit and diagnostic cleanup completed; recurring cellular DHCP renewal failure remains unresolved. This is not a firmware release or a claim of permanent stability.

## Device and scope
Native OpenWrt 24.10.8, Linux 6.6.144, notion,r281, EasyMode 4.2.3. The router had over five days of uptime at the final check. All times below are Philippine time (UTC+8).
Current configuration was backed up privately. Newer user settings and installer files were preserved. No firmware flash, factory reset, router reboot, radio band change, service removal, or permanent network configuration change was performed.

## Findings reconciled with logs
- 2,317 health samples cover 01:10:42–21:02:53. Fourteen probes failed; these are samples, not fourteen separate outages.
- At 08:39:51, 08:40:26, and 08:41:01, cellular probes failed consecutively. The watchdog began a modem reconnect at 08:41:06; the new DHCP lease was obtained at 08:41:24. Available AP memory at these failures was about 24,100 KiB.
- Additional short probe failures occurred around 10:03, 11:10–11:15, 15:25–15:45, and 16:18. At 15:40:24 a no-link sample coincided with DHCP lease expiry.
- Repeated 7,200-second modem DHCP leases expired after unanswered renewals. Examples: 03:05:46, 05:05:32, 07:05:19, 10:41:13, 13:40:37, 15:40:24, 17:40:10, and 19:39:57. Fresh discovery/select acquired a lease within roughly one second in the logged examples. Interface down/up and firewall reload events accompanied expiry.
- Live packet capture reproduced the distinction: outgoing unicast and broadcast renewal requests had no visible reply; a subsequent fresh discovery/select received OFFER and ACK immediately. The precise modem-side reason is not established. The longer 08:41 outage is not proven to have the same cause.
- IPv6 no-default-route warnings are separate from proof of an IPv4 outage. Wi-Fi roaming messages also do not by themselves demonstrate a cellular outage.
- The history minimum MemAvailable was 15,824 KiB, and failed probes occurred with approximately 21–29 MiB available. No OOM evidence was found in the captured kernel log. The modem processor separately reported around 62,820 KiB available. These observations do not support memory exhaustion as the recorded outages' cause.
- Connection tracking used 246 of 15,360 entries in the initial snapshot. CPU load was low. Required DNS, wireless, modem, and management services were retained.

## Controlled tests and changes
1. A manual DHCP renewal at 11:40 reproduced failure, followed by successful fresh acquisition at 11:40:52. This diagnostic caused a brief lease interruption.
2. At 20:57, a temporary rule changed only the source address of outgoing cellular DHCP renewal traffic. It had a timed automatic rollback. It did not fix renewal; fresh acquisition succeeded at 20:57:41. The rule was removed and the final firewall table inventory confirmed it absent. This test also caused a brief lease interruption. It was not installed as a fix.
3. Archived four old diagnostic paths to the laptop, verified their archive, and removed them from router RAM: two old portal/relay audit directories and two compiled test artifacts. Temporary filesystem usage decreased by approximately 800 KiB. User SMS, current diagnostics, settings, and BlazePwifi installer archives were preserved. This is a modest memory cleanup, not a cure for the cellular fault.

BusyBox's upstream documentation/source distinguishes DHCP renewal from initial selection; the device's packet capture is the evidence for the failure here: [upstream DHCP client changes](https://lists.busybox.net/pipermail/busybox-cvs/2021-February/040164.html).

## Final verification
At 21:04–21:06:
- Cellular-bound ICMP: 10/10 replies from one independent target and 5/5 from another; average RTT approximately 109 ms and 73 ms respectively.
- Local DNS successfully resolved OpenWrt's domain.
- Cellular HTTPS connectivity test returned HTTP 204.
- EasyMode returned HTTP 200; Advanced redirect page returned HTTP 200.
- LuCI's unauthenticated HTTP 403 contained its normal login form. Login with the configured credentials succeeded, and authenticated LuCI status returned HTTP 200.
- Temporary DHCP trial table absent; standard firewall table remained.
- Router uptime continued through all work, with no reboot.
- Final available RAM fluctuated around 22–25 MiB. A short successful test cannot establish long-term stability.

## Remaining work
The repeat DHCP-renewal failure requires further modem-side packet/driver evidence and a validated correction. The separate longer cellular stall also remains open. Do not treat a longer lease, disabled watchdog, static cellular address, or suppression of lease expiry as a proven fix.
The previously prepared reset-defaults firmware was not flashed in this audit and predates newer user settings. This audit does not establish reset persistence or update the old encrypted installer package.

Raw logs, packet captures, modem identities, credentials, and backups remain private on the user's laptop. No private archive or unencrypted firmware was included in this report.
